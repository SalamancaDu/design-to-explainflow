# Learning Capture

Use this file to extract reusable design knowledge after a gate review or full run review.

## Learning types

### Gate learning

Save when a stage rule prevents repeated failure.

Examples:

- a native-alpha or conditional fallback decision that prevents recurring edge damage
- a typography gate that prevents logo drift
- a motion readiness gate requiring a composite preview before animation

### Prompt learning

Save when a wording pattern consistently improves output.

### Layout learning

Save when a composition rule improves clarity.

### Image style learning

Save when a visual treatment fits the project.

### Motion learning

Save when timing or movement improves comprehension.

## Capture template

Use this structure for run notes or proposed skill deltas:

~~~markdown
## Review learning: <short name>

- Gate / asset type: <prompt / typography / image / layout / PNG / motion / run>
- Context: <video topic or use case>
- What worked or failed: <specific decision>
- Why it mattered: <reason tied to stage, role, clarity, style, or craft>
- Reuse when: <future scenario>
- Avoid when: <scenario where it would fail>
- Suggested prompt phrase: <optional>
- Suggested target: <skill reference / run note only>
~~~

## Update decision

- If it applies broadly across future projects → propose updating a skill reference.
- If it applies to one video or campaign → keep it in the task or an existing requested run note; do not automatically create a record.
- If it is only a defect fix → do not save as a rule; just fix it.
- If it conflicts with existing rules → identify the owning rule and applicable authorization; update within an already authorized maintenance scope, asking only when the conflict creates a consequential unresolved choice.

## Skill update rules

When updating skill references:

- revise the owning clause and synchronize affected examples or references; add a concise new clause only when it has a distinct necessary role;
- do not paste long reviews;
- do not duplicate existing rules;
- keep examples generic and reusable;
- mention the source run only if needed for traceability.

## Optional example cues

When learning capture is requested or a reusable finding is established, examples include an overlay-safe title placement, readable data-label hierarchy, a theme-matched paper texture, a reliable cutout prompt, a six-second chart reveal, or a useful keyword hold. These are prompts for evidence-based reflection, not required outputs or permanent rules.
