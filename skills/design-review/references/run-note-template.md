# Run Note Template

Use when the user requests a persistent review record or the project already requires one. A completed creative run alone does not require a new file.

~~~markdown
# Design Review: <project name>

## Brief

- Date:
- Asset type:
- Current stage:
- Proposed next stage:
- Goal:
- Tools and implementation version when relevant:
- Requested outputs and actual completed stage:
- Sound mode and timing basis (actual audio / fixed silent timing / provisional timing for pending narration):

## Gate verdict

- Verdict: PASS / PASS WITH NOTES / REVISE BEFORE NEXT STAGE / GO BACK A STAGE / REDO / BLOCKED
- Reason:
- Next-stage quality conditions met / missing:

## Outputs

| Output | Path | Stage | Verdict | Notes |
|---|---|---|---|---|
|  |  |  |  |  |

## Strongest decisions

- Decision:
- Why it worked:

## Blocking problems

- Problem:
- Cause:
- Fix:

## Prompt / layout / image / motion learnings

- Learning:
- Reuse when:
- Avoid when:
- Suggested target: skill update / run note only

## Next iteration

- Change:
- Expected improvement:
~~~

Keep run notes concise. They should help the next production, not become long essays.
