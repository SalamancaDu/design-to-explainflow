# 工作流总览

这套系统用于把信息排版、视觉素材、标题字和短片段动效连接成可复用的生产流程。主要适用于财经解释、纪录片、编辑式封面、海报、信息图和视频图文资产；具体工具由交付要求和已有项目决定。

## 先确定交付，再选择链路

开始时从已有上下文确认用途、受众、比例、准确内容、已有素材和最终交付。只有缺失信息会实质改变结果时才询问。用户只要分析或提示词时，交付到该范围；要求完整制作时，在已有授权内连续完成，保留用户明确指定的选择或审阅节点。

文字是否可编辑与画面是否运动是两个独立判断：

| 路由 | 条件 | 生产方式 |
|---|---|---|
| A 静态整图 | 单张静态图，不要求内部元素可编辑，主要表达氛围、构图或情绪 | layout-design → image-style → imagegen（需要新位图时）→ 结果检查与交付 |
| B 可编辑静态合成 | 最终是静态图，但文字、数字、图形或素材需要准确控制、修改或复用 | layout-design → image-style / title-text-design（按需）→ 素材制作 → 准确排版与静态合成 → 检查与导出 |
| C 整帧动效 | 已有或新建整图，只需推拉、裁切、遮罩、整体移动或新增叠加元素 | 检查静帧 → motion-style → 选定工具实现 → 预览、导出与检查 |
| D 逐元素动效 | 主体、标题、数字、图表或其他元素需要独立变化 | 运动意图与 layout-design → 视觉母版 → 按运动需要拆层 → 静态合成 → motion-style 详细方案 → 选定工具实现 → 预览、导出与检查 |

整图可以用于 C；只有需要独立控制其内部元素时，才需要重建或拆层。进入剪辑软件不自动意味着 D。只有文字可编辑的静态图走 B，不必进入动画工具。

## 核心分工与交接

| 环节 | 负责什么 | 交给下一步什么 |
|---|---|---|
| layout-design | 信息层级、版式、留白、阅读顺序、安全区域 | 准确内容、排布约束、选定路由；涉及动效时写明哪些元素需要变化 |
| image-style | 非文字素材的视觉方向、配色、光影、材质和生成策略 | 位图清单、参考图角色、提示词及保持不变的视觉约束 |
| title-text-design | 按需设计定制标题字的骨架、逐字结构和主题符号 | 准确标题、字形方案及所需标题资产；普通排字不必调用 |
| imagegen | 在授权范围内生成或编辑需要的位图 | 已检查并保存到项目的实际素材路径、尺寸及透明信息 |
| 合成工具 | 准确文字、数据图形、素材定位和静帧 | 含真实内容的 composite-preview 与可编辑源文件 |
| motion-style | 拆层前的运动意图；静帧成立后的节奏、动作、停留和转场 | 对应元素的动作与时间说明、声音模式与时间依据、交付要求 |
| 实现工具 | 将动效方案制作成实际动画并导出 | 可预览源文件和要求的成片 |
| design-review | 对具体产物和下一步做质量判断 | 有依据的问题、修复位置及是否具备下一步条件；评分和经验沉淀按需 |

HyperFrames 是可选的合成与动效实现工具。使用前按[调用索引](skill-index.md)确认入口与项目版本，不同时混用多套技术约定。

## 稳定原则

- 先信息，后风格；分层用于后期控制，不是审美起点。
- 新的复杂视觉方向先建立母版；已有可用素材或明确设计可以直接复用，不为走流程重复生图。
- master-frame-preview 确定色彩、光影、材质、镜头和主视觉比例；composite-preview 检查准确文案与素材合成后的完整画面。前者不能替代后者。
- 拆层前先说明哪些元素需要动以及为什么；详细时间轴在静态合成成立后确定。
- 中文正文、精确数字、需要修改的标题和数据关系保留为可编辑内容。定制标题可作为经逐字检查的独立位图资产，源文本仍须保存。
- 真实数据图形由明确数值、单位、时间范围和计算规则绘制；机制示意与视觉隐喻不得冒充精确数据或真实证据。
- 生成素材优先采用当前工具支持的原生透明输出；最终检查实际 Alpha 和合成边缘。
- 质量检查是执行中的判断，不自动成为用户审批。用户保留的审阅节点及实际外部操作授权仍须遵守。
- 区分方案完成、静帧完成、动画预览通过和成片已导出；只能报告实际取得的证据。
- 需要保存多份资产或复用时使用 run 目录，片段用独立编号；局部修改沿用现有项目，不创建空流程文件。
